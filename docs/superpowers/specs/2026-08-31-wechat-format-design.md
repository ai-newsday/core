# 公众号版式与文风设计（2026-08-31）

> 源头：用户要开始定点发公众号和其他平台。公众号侧手动发布——用 [doocs/md](https://github.com/doocs/md) 把 Markdown 渲染成公众号排版，**我们只需要产出 md**，不做自动推送。
> 参考文风：用户自己的 AI 周报 `neverbiasu.github.io/src/zh/posts/ai-weekly`。

## 目标

产出一份**公众号专用的 Markdown**，粘进 doocs/md 就能直接发；同时补齐两样现在完全没有的东西：**文章标题**和**摘要**。

## 现状（2026-08-27 真实成品，`content/posts/2026-08-27.md`）

九条内容，逐条形如：

```markdown
### GLM-5.3-Flash 发布：320B 参数模型仅 18B 激活，推理成本降至前代 1/10

智谱发布 GLM-5.3-Flash，这是 GLM-5 系列首款原生多模态模型……

#GLM-5.3-Flash #多模态模型 #模型量化
[6] · 96 分
```

看出来的问题，逐条都有实据：

| 问题 | 实据 |
|---|---|
| 分数对读者无意义 | 九条评分 `97/97/96/99/96/96/100/100/94`，全挤在 94-100，零区分度，且暴露内部实现 |
| 混进未解读条目 | 第 5 条标题是仓库 slug `zai-org/GLM-5.3-Flash`，正文是 README 原文倒灌，含一个嵌在文章中间的 `# H1` 和会被渲染成代码块的缩进行，内容是"加微信群/看博客/用 API" |
| 重复 | 第 5 条和第 6 条是同一个模型（zai-org 原始 + unsloth 量化） |
| 标签会被微信截断 | `#Qwen3.8-Flash-Next` 在 `.` 处断成 `#Qwen3`；`#GLM-5.3-Flash` 在 `-` 处断成 `#GLM`。9 条里 2 条中招 |
| 无标题、无摘要 | 文章标题恒为 `AI Daily · <date>`；`今日看点` 一句没有 |
| 正文无视觉落点 | 九段等密度纯文字，零加粗。手机窄栏下是九块灰色色块 |

> **`今日看点` 缺失的原因已查明且已修**：渲染器早就有这个槽位（`publish.py:269`），Hugo front matter 的 `summary` 字段也在用它（`:243`）。之前恒为空是因为 `daily_take` 的 LLM 调用一直失败（ModelScope 生产 0/153 全 429）。#123 合并后实测 `daily_take` 正常产出——所以**明天的网站版会第一次带上今日看点**，不需要新做机制。

## 不做什么

- **不做自动推送**。只产 md，人工粘贴。
- **不改条目标题的钩子风格**。参考周报用的是 `名字：一句话说明` 的描述式；现在这套 `0.22B 反超 11.9B：…` 的数字/反差钩子在公众号里更抓人，**保留**。
- ~~不做目录~~ **2026-09-03 撤销**：用户连续两天要求加目录（9-01 手动加回、9-03 明确指出缺失），推翻了这条判断。当初的理由（锚点在公众号里跳不动）依然成立，但目录的价值不在于能不能跳转——是让读者进正文前先扫一眼今天有哪些条目，公众号里同样成立。见下方「2b. 目录」。
- **不做封面图**。逐条配图另见 #124；封面图是人工挑的事。
- **不改网站版的既有版式**。网站那份继续照现状渲染。

## 1. 两份文件，不是一份

新增 `content/wechat/<date>.md`，与现有 `content/posts/<date>.md` 并存。

公众号版**不含**三样粘进 doocs/md 会变成垃圾的东西：

1. **Hugo front matter** —— `---\ntitle: …\ndraft: true\n---` 会被渲染成一条分割线加几行乱码文字。
2. **站点页脚** `RSS · 历史归档 · 主站 ｜ AI News Daily`。
3. **`# AI Daily · <date>` 一级标题** —— 公众号的标题在编辑器的标题栏里，正文不该再重复一个 H1。

## 2. 文章标题（新增产出）

格式固定：

```
{事件1} | {事件2}【AI日报】
```

- **≤64 字**（含分隔符与后缀）。
- **默认放 2 个事件**，只在两个事件都明显偏短时放第 3 个。这是算出来的硬账：`【AI日报】` 占 6 字、每个 ` | ` 占 3 字，64 字里只剩约 52 字分给事件；而模型名本身很长（`GLM-5.3-Flash` 一个词就 13 字）。实测一条三事件标题正好卡到 64 字、毫无余地。
- 每个事件写成「主体 + 动词短语 + 结果」，12-20 字，主体在最前当钩子。模型名/公司名保留英文原文。
- 挑**影响面最大**的事件，不是分数最高的。
- 不用「重磅/炸裂/速看」，无感叹号，无 emoji。

**只用于公众号。** 网站版继续用 `AI Daily · <date>`——站点标题是归档与 URL 的稳定标识，公众号标题是拉开率工具，两者职责不同。

## 3. 摘要（复用 `daily_take`，改格式）

格式固定：

```
今日亮点：{描述1}；{描述2}；{描述3}。详见正文，参考链接见文末。
```

- **≤120 字**。开头 5 字 + 结尾 13 字固定，约 100 字留给描述。
- 2-3 段，`；` 分隔，每段「主体 + 做了什么 + 关键数字/结果」约 30 字。
- 前两段对应标题的两个事件，第三段可补一件标题没放下的。
- 只用条目里出现过的事实与数字，**不得编造**；数字拿不准就不写数字。

**同一份文本同时用于网站的 `今日看点` 和 Hugo `summary`**，不额外生成第二份、不多花一次 LLM 调用。

代价要说清楚：现有 `daily_take.md` 要的是「3-5 句宏观趋势判断，有观点」，改成摘要式之后**失去了那层编辑判断**。取舍理由是公众号摘要栏是刚需且有硬长度限制，而"有观点的趋势判断"目前既没被渲染出来过（一直是 None），也没有证据说明读者需要它。若日后想要回来，再加独立字段。

### 长度必须用代码校验，不能只靠 prompt

spike 实测：prompt 里明写「必须 ≤120 字」，模型产出 **145 字**；标题写「≤64 字」，产出 49 字（额度没用满，可接受）。**长度约束靠 prompt 约不住。**

处理方式沿用本仓库既有纪律（`build_ok_item` 在 tags 数量不达标时抛错、调用方回退）：

- 摘要超长 → 重试一次；仍超长 → 用 `_trim_to_sentence` 截到句末（该函数已存在）。
- 标题超长或不含 `【AI日报】` → 重试一次；仍不合规 → 回退为 `AI Daily · <date>`，**不截断**（截断会切掉后缀，产出半截标题比朴素标题更糟）。

## 3b. 目录（2026-09-03 新增）

摘要下方、第一条正文之前，插一段无锚点的编号列表：

```markdown
## 目录

1. {条目1标题}
2. {条目2标题}
...
```

- 纯文本编号，**不带链接**——公众号锚点跳不动，硬做链接只会让读者点了没反应，比不做更差。
- 条目标题取正文里已经生成的钩子标题（跟 `## 条目标题`/参考链接表用的是同一份文本），不重新概括、不截断。
- 编号顺序与正文、参考链接表严格一致，删条目时三处一起重排（沿用 §5「删除应发生在审阅阶段」的既有结论）。
- 价值不在于跳转，在于**扫读**：读者进正文前先看到今天有哪些条目，再决定要不要往下翻——这条在锚点失效的前提下依然成立，是当初判断的盲点。

## 4. 逐条版式

```markdown
## {钩子标题}

{正文，关键信息加粗}[n]

#标签1 #标签2 #标签3

---
```

相对现状的改动只有三处：

> **2026-09-02 更正**：本节原写 `###`，用户实测后改用二级标题 `##`——与文末 `## 参考链接` 同级，便于 doocs/md 按标题层级套统一样式。代码与本节均已改为 `##`。

1. **删掉 `· NN 分`**，整行消失。
2. **`[n]` 保留**，但从独立一行移到正文末尾，作为引用角标。
3. **条目之间加 `---`**。

逐条配图（#124，已落地）插在 `##` 标题与正文之间。

### 正文加粗（改 `interpret_item.md`）

给**机构名/公司名、模型名、关键数字**加粗，每段 2-4 处。不整句加粗，不给形容词或结论句加粗。

理由：参考周报每条都有配图，视觉落点由图承担；我们（在 #124 落地前）没有图，全靠加粗撑。手机窄栏下，一段没有落点的密集中文很难扫读。

**这条同时影响网站版**（同一份 body）。加粗在网站 Markdown 里正常渲染，判断是两边都受益。

### 标签清洗（纯函数 + prompt 双层）

微信话题标签**遇到符号即截断**，所以：

- **prompt 层**：标签只用字母或汉字，不含数字、连字符、点、斜杠、空格；用公司名/产品线/概念的通名，不带版本号——写 `#GLM` 不写 `#GLM-5.3-Flash`。
- **代码层**（兜底，因为 LLM 必然违反）：取标签开头**连续的字母或汉字**段。
  - `GLM-5.3-Flash` → `GLM`
  - `Qwen3.8-Flash-Next` → `Qwen`（在数字处即断，不是 `Qwen3`）
  - 截断后不足 2 字符 → 退回"仅去除符号"，避免 `#3D生成` 这类被清空。

两层都要，是因为微信的实际截断行为就是这个规则——与其让它在读者那边断，不如我们先断好。

## 5. 条目筛选

- **排除 `interpretation_status == "extractive_fallback"` 的条目。** 它们按定义是"没解读成功"，标题是英文原文、正文是原始摘要，放进公众号就是上面第 5 条那种。
  - 代价：LLM 大面积失败的日子，公众号版可能只剩五六条。#123 之后回退率实测 2%（此前 44%），这个代价已经很小。
- 重复条目由故事线合并（#119）处理，本 spec 不另做。
- 用户可能删掉一两条：**删除应发生在 TG 审阅阶段（drop 决策）**，流水线重新渲染，编号自然连续。手改 md 会导致 `[n]` 与参考表错位。

## 6. 参考链接

有序列表，正文按顺序 `[1] [2]` 引用——**结构与现状一致**（`_render_references` 已经是 `1. [label](url)`）。

公众号版唯一的差异：**用 `1. {标题} — {裸 URL}`，不用 `[标题](url)`**。公众号里 Markdown 链接渲染成不可点的彩色文字，反而把地址藏起来了；裸 URL 至少能被读者复制。

## 7. 数据流

```
review → build_report()  →  DailyReport（现状不变）
                          ├→ render_markdown()      → content/posts/<date>.md   （网站，现状不变）
                          └→ render_wechat()（新增） → content/wechat/<date>.md （公众号）

daily_take（改 prompt 为摘要格式）→ 同时供给网站今日看点 / Hugo summary / 公众号摘要
文章标题（新增 LLM 产出）        → 仅公众号
```

`render_wechat()` 与 `render_markdown()` 同为纯函数，同一个 `DailyReport` 入参，可离线快照测试。

## 8. 测试要点

- 标签清洗纯函数：`GLM-5.3-Flash`→`GLM`、`Qwen3.8-Flash-Next`→`Qwen`、`#具身智能` 不变、`#3D生成` 不被清空。
- 长度校验：摘要超长走重试再截断；标题超长回退为朴素标题且**不产出半截后缀**。
- 筛选：`extractive_fallback` 条目不出现在公众号版；全部回退时公众号版不报错（可以很短，但结构完整）。
- 渲染快照：公众号版不含 front matter、不含站点页脚、不含 `# AI Daily` H1、不含 `· NN 分`。
- 参考链接：公众号版是裸 URL，网站版仍是 Markdown 链接；两版编号与正文角标一致。
- prompt 内容测试：标题/摘要规则串在 prompt 里存在。

## 未决问题

1. **条目顺序。** 现状按 `genre_labels` 键序分组顺读。分数删掉之后排序依据是否要变（例如与标题呼应、把标题点到的事件提到最前）——**尚未与用户确认**，实现阶段先保持现状不动。
2. **doocs/md 的"外链转底部引用"开关**是否开启。若开启，它会对正文里的 Markdown 链接再做一次底部引用，与我们自己的参考表叠加。本 spec 选择正文不放 Markdown 链接（只有 `[n]` 角标 + 文末裸 URL），因此两种设置下表现一致——但值得实际粘一次确认。
