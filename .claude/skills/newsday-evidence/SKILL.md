# ai-newsday 证据纪律

`manager-harness` 负责角色、汇报结构和决策边界。这里只放**本仓库用真实代价换来的**东西。

## 一、提方案前先量它依赖的信号

四次实测里**三次推翻了动手前的方案**:

| 方案 | 实测结果 |
|---|---|
| 配图按体积过滤掉图标 | 图标 101KB **大于**真插图 38KB, 方案作废 |
| 抓 README 补论文机构 | 三个真实页面里一个只有 shields.io 徽章, **会把徽章当配图** |
| `ltx_role_affiliation` 提机构 | 该字段装的是标签词加一个残留 `[`, 10 篇提取到 **0** 篇 |
| 按账号做同源惩罚压刷屏 | 被投诉的三条 77/70/69 分, 而池子第 12 名 90 分 —— **它们进成品是因为用户 keep, 跟分数无关**, 这个杠杆够不着 |

先量的成本是几分钟, 白干的成本是半天加一次错误的 issue。

**具体做法**: 写实现前, 先拿 `data/runs/*/` 的真实产物或 `gh run view --log` 的真实日志,
验证方案依赖的字段/信号确实存在且区分度够。

## 二、"测试全绿" ≠ "生效了"

这条在本仓库反复出事:

- `#146` 标题选题规则测试全绿, 当晚 provider 故障, **模型认不认那套规则至今没验证过**
- `#119` 故事线合并测试全绿并合并, 但实体正则拿 10 个真实模型名测**只匹配 2 个** —— 上线起基本空转
- `#176` 摘要收尾测试全绿, 生产却产出 `；详见正文` —— 修补顺序错了, `_trim_to_sentence` 会把
  刚 strip 掉的分隔符重新截回来

汇报时**分开写**: 单元测试通过 / 真实数据验证通过 / 生产跑过一次。三者不能互相冒充。

## 三、函数写对了但没人调用

同一类失效出现过两次:

- `wechat_title` 一路穿过类型定义, **四个调用点全用默认值 `None`** —— 测试直接给
  `ReviewResult` 赋值, 绕过了 `review()`
- `clean_wechat_tags` 单测全绿, **没接进渲染** —— 读者看到的截断一模一样

**所以**: 新增纯函数时, 必须另写一条**接线测试**, 走 `run_finalize_tick` 之类的真实路径,
而不只测函数本身。

## 四、改配置/阈值前先算它会不会必然触发

`quota` 各项之和恰好等于 `total_limit`(3+3+3+2+1 = 12), 所以**任何类型分布不均的一天**,
per-genre 上限都必然先于总量生效 —— 用户 keep 了 10 条只发出 7 条。

这不是参数调错, 是两个约束的**数值关系**决定了谁先生效。改阈值前先算清楚边界条件。

## 五、生成物的日期与重跑

- 报告标的是**发布日**(伦敦午夜后发 = 北京早上八点), 不是运行日
- 同一份刊物重跑必须落回**同一个** `date_label`, 否则会被当成新的一天, 把昨晚已发的条目全部重新放行
- 两次运行落进同一个 label 会让跨天去重的"同 label 视为重跑"豁免整个失效 —— 2026-09-04 因此连发两天重复条目
